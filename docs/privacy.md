# 隐私与脱敏说明（v2.1.0）

本文说明报文日志、设备自由文本与错误上报的脱敏规则。脱敏**默认开启、写入时执行、没有关闭入口**：
`InMemoryPacketLog.record` 先对帧载荷脱敏，再生成 HEX 与摘要，因此 TEXT / JSON / CSV
三种导出格式、复制到剪贴板和界面展示拿到的都是同一份已脱敏数据。

## 1. 脱敏规则表

| 命令 | 方向 | 字段 | 处理 | 保留内容 |
| --- | --- | --- | --- | --- |
| `AUTH` | TX | `mode` 之后的整段 `credential`（令牌 / 随机数 / 签名凭据） | 全部字节替换为 `*`（`0x2A`） | `mode`、`credentialLen` |
| `AUTH` | RX（成功） | `token` 值、`challenge` 值 | 全部字节替换为 `*` | `status`、`tokenLen`、`expiresIn`、`challengeLen` |
| `AUTH` | RX（失败） | 无敏感字段 | 原样保留 | 错误详情，便于排障 |
| `GET_DEVICE_INFO` | RX（成功） | `serialNumber` | 保留前 4 字节，其余替换为 `*` | `vendor`、`model`、`hardware`、`firmware` |
| 其他命令 | 任一 | 无 | 原样保留 | 完整载荷 |

不变式：

- **长度不变**：只替换字节值，帧长度、字段偏移与 CRC 仍可按原协议解析；
- **不可还原**：掩码字节不携带任何原文信息，导出文件无法恢复 credential/token/签名；
- **三格式一致**：脱敏发生在写入阶段，导出层不再做二次处理，因此 TEXT/JSON/CSV 一致；
- **非敏感命令不受影响**：`redactPayload` 在没有敏感字段时返回原数组，不产生额外分配。

实现位置：`core/src/commonMain/kotlin/com/valhalla/core/logging/PacketLogRedaction.kt`。

## 2. 设备标识

MAC / deviceId 不在协议 payload 中；若导出或界面需要展示，提供两种不可逆或半可读方案：

| 方法 | 输出示例 | 用途 |
| --- | --- | --- |
| `maskDeviceId` | `AA:B**********`（长度不变） | 需要人工辨认前缀的排障场景 |
| `hashDeviceId` | `dev#1a2b3c4d`（FNV-1a 32 位，稳定） | 需要区分设备但不应暴露原值的导出字段 |

设备信息应答中的 `serialNumber` 在写入报文日志时已截断为「前 4 字节 + 掩码」。

### 2.1 自由文本字段级脱敏（v2.1.0）

固件回传、设备日志与错误消息无法按协议结构定位，统一由
`SensitiveTextRedaction`（`core/logging/SensitiveTextRedaction.kt`）按正则规则过滤。
**入库前**（`InMemoryDeviceLogger.log`、`DeviceProfileCodec.encode`）与**上报前**
（`RemoteErrorDispatcher`）执行，因此 UI、导出与远端载荷拿到的是同一份脱敏结果。

| 形态 | 规则 | 输出示例 |
| --- | --- | --- |
| PEM 块（公钥/证书/私钥） | 整块替换 | `[REDACTED PEM]` |
| `token=…`、`credential=…`、`secret=…`、`password=…`、`signature=…`、`nonce=…`、`serialNumber=…`、`deviceId=…`、`authKey=…` | 保留标签与分隔符，值替换为 `***` | `token=***` |
| MAC 地址 `AA:BB:CC:DD:EE:FF` | 保留前 2 位，其余每段替换为 `**` | `AA:**:**:**:**:**` |
| UUID | FNV-1a 32 位哈希 | `dev#1a2b3c4d` |
| 连续 ≥ 32 位十六进制 | 整体替换 | `[REDACTED KEY]` |
| 无标签 ≥ 40 位 Base64 | 整体替换 | `[REDACTED B64]` |

不变式：

- 规则幂等：重复执行不会继续套娃，便于入库前与导出前二次兜底；
- 普通文案不受影响（版本号、耗时、百分比等测试断言原样保留）；
- 设备档案的 `deviceId` 是主键，必须保留原值用于匹配；导出到用户可见位置时仍需用
  `maskDeviceId` / `hashDeviceId` 处理。

## 3. 本地存储与上传

脱敏影响报文日志、设备日志、设备档案自由文本字段与错误上报载荷。本地持久化仍包含
设备档案、OTA 断点、鉴权令牌与偏好，其位置与 key 见隐私页（`StorageInventory`）。

`RemoteErrorReporter` 是**可插拔接口**，当前默认装配为 `NoopRemoteErrorReporter`，
未接入任何真实远端 SDK，也没有网络请求。接入时替换实现并在应用入口构造
`RemoteErrorDispatcher`（批量、异步、可关闭）；载荷字段在进入调度器时即完成脱敏。
Android manifest 仍未声明 `INTERNET`，导出文件只通过系统保存/分享面板交给用户。

## 4. 验证与限制

自动化测试（JVM 宿主）覆盖：

- `PacketLogRedactionTest`：`AUTH` credential/token/challenge 掩码、序列号截断、
  非敏感命令不变、三种导出格式一致、设备标识哈希稳定；
- `SensitiveTextRedactionTest`：标签值、MAC、UUID、长十六进制、PEM、幂等与普通文案不误伤；
- `RemoteErrorReporterTest`：上报载荷不含 token/credential/序列号/MAC/密钥片段，批量切分与关闭清空；
- `DeviceTextRedactionStorageTest`：设备日志入库与设备档案编码后敏感串消失。

未验证：

- 真机系统分享面板、第三方应用读取导出文件的行为；
- 真实远端 SDK 的网络传输与重试（接口就绪，但未接入服务）；
- 设备固件是否会在自由文本中输出未知格式的标识（规则表外的形态无法自动识别）。

## 5. v2.5.0 新增本地数据与上传边界

- **固件库**只保存元信息（文件名、版本、渠道、型号白名单、大小、CRC-32、时间与结果）
  与平台文件引用，**不复制固件二进制**；不包含令牌、密钥、设备档案或报文内容。
- **事件时间线**每设备最多 100 条，摘要/详情/错误码落盘前统一脱敏；读取走本机键值存储。
- **一键诊断报告**完全由本机快照生成：设备 ID 只输出不可逆短哈希，自由文本与报文逐条脱敏；
  报告只经系统保存/分享面板交给用户，不自动上传。
- **本地提醒**在系统通知中心展示，不新增网络权限，也不进入远端上报通道。

## 6. v2.6.0 新增本地数据与上传边界

- **设备指标采样**：仪表盘在本机记录最近 50 个电量/RSSI 点（含时间戳），按设备 ID 分键存储；
  只用于本机折线，界面明确标注「本机采样，非设备历史」，不进入任何上传通道。
- **设备体检**：顺序执行真实指令并把结论（含设备错误码）保存在内存；结果仅在本机展示，
  复制/保存为文本时沿用 `SensitiveTextRedaction`，不新增远端上报。
- 固件升级向导不新增数据面：仍使用既有预检、断点与 OTA 状态机。

## 7. v2.7.0 新增本地数据与上传边界

- **配置预设与自动化规则**存入既有应用偏好键（`CONFIG_PRESETS` / `AUTOMATION_RULES`），
  只包含配置值、预设名称与规则定义，不含设备档案、令牌或报文内容。
- **使用统计**只在本机聚合设备档案、OTA 历史与事件时间线，不新增存储、不做估算、
  不上传；界面明确标注「仅本机统计，不上传」。
- **偏好与预设备份**导出白名单字段（语言、主题、重连策略、日志容量、导出默认值、预设、
  自动化规则、引导标记），明确排除令牌、密钥、凭证、设备档案、日志与断点；
  导入只在本机写回偏好，恢复出厂设置不删除设备档案与令牌。
- 自动化规则只在前台本地触发，不申请后台权限，也不新增网络权限。

## 8. v2.8.0 实时信号、通知与诊断包边界

- **实时 RSSI** 只读取系统 BLE 回调并写入既有 50 点/设备采样，不新增网络请求；
- **本地通知** 只在本 App 存活期间送出，不承诺进程被杀后提醒，不新增后台任务或远程推送；
  权限被拒时降级为应用内横幅，不再反复弹窗；
- **诊断包** 只包含白名单条目：manifest、体检报告、连接质量、脱敏报文、设备档案摘要、
  版本构建信息与指标采样；明确排除令牌、密钥、凭据、断点文件、固件二进制与未脱敏原文，
  自由文本写入前再次经 `SensitiveTextRedaction` 脱敏，manifest 标注 `redacted=true`；
- 诊断包生成在内存中完成，取消或失败不落文件，也不会上传。

## 9. v2.9.0 批量、固件库与队列边界

- **批量操作**不新增持久化：逐台状态与汇总保存在内存中；汇总文本只输出设备显示名与不可逆
  deviceId 短哈希，复制或保存沿用既有脱敏与文件通道，不上传。
- **固件库**仍只保存元数据（文件名、版本、渠道、型号白名单、总字节、CRC32、来源路径、
  别名、收藏与最近使用时间）与平台文件引用，不复制固件二进制，也不记录令牌或设备档案；
  条目失效只在本机标记并提供重新选择入口。
- **OTA 队列**只在内存中维护队列状态，不新增存储；每台设备的断点仍写既有断点存储，
  复用前经过既有四重门控；退出 App 队列即中断，不做后台续跑。
- 批量执行期间的设备写锁（`DeviceOperationLocks`）只在内存中，进程退出即释放。
