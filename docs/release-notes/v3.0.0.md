# v3.0.0 - 工程收口与真实资源

- 版本：`3.0.0`（`versionCode 30`）
- 基线：v2.9.0（远端 `b405a4e`）
- 主题：工程收口 + 真资源；不新增业务功能

## 1. 静态分析（detekt + ktlint）

- 根工程统一接入 detekt 1.23.8 与 ktlint-gradle 14.2.0，各模块可单独执行：
  `./gradlew detekt`、`./gradlew ktlintCheck`、`./gradlew ktlintFormat`。
- detekt 保留官方默认规则集，只按项目现状调整复杂度、行宽与命名阈值，未关闭规则；
  ktlint 使用 `ktlint_official` 风格，仅通过 `.editorconfig` 的官方注解豁免放行
  `@Composable` 的 PascalCase 命名。
- 首次全量分析 406 条：本轮修复 15 条（异常抛法规范化、返回数收敛、长行拆分等），
  基线保留 391 条（core 266 / data 10 / feature 115 / composeApp 0），逐条原因见
  [static-analysis-baseline.md](../static-analysis-baseline.md)。
- CI 新增 `static-analysis` job：`detekt` 与 `ktlintCheck` 任一失败即 job 失败，并上传日志与报告。

## 2. 测试覆盖率（Kover）

- 接入 Kover 0.9.11，只统计 JVM 单元测试，不统计 Android instrumented。
- 三模块独立阈值与校验任务：core 行覆盖 ≥ 75%、data ≥ 55%、feature ≥ 60%；
  未达标时 `koverVerifyJvm` 直接失败，不放宽阈值。
- feature 的 `com.valhalla.feature.ui` 包按可测范围排除：Compose UI 需要 Android/iOS 渲染环境，
  JVM 单测无法执行；其余逻辑仍按 60% 硬阈值校验。
- 实测行覆盖：core 94.32%（5379/5703）、data 87.55%（408/466）、feature 89.39%（6409/7170，排除 UI 包后）。
- CI 新增 `coverage` job：生成 XML/HTML 报告、执行阈值校验，并始终上传 `kover-reports` artifact。

## 3. 存储 schema 迁移管线

- 新增集中入口 `com.valhalla.core.storage.StorageSchemaMigrator`、`StorageKind` 与
  `StorageMigrationStatus`；版本号只在 `StorageKind` 维护。
- 覆盖五类本地数据：偏好存储（v2）、设备档案（v1）、OTA 断点（v1）、指标采样（v2）、
  偏好备份文件（v2）。
- 旧版本数据按迁移步骤逐级升级；未知/未来版本不改写原数据，回退安全默认并向用户提示；
  损坏数据给出具体原因，不静默丢弃、不崩溃。
- 真实迁移路径：
  - 偏好 v1 → v2：旧值 `zh-Hans` / `dark` 规范化为 `CHINESE` / `DARK`，并写入
    `storage_schema_version=2`；
  - 指标采样 v1 → v2：旧格式字符串升级为 `v2` 版本头并保留样本；
  - 偏好备份 v1 → v2：导入时识别旧版本并按当前结构解析；
  - 未来版本备份（如 v3）回退默认值、生成 warning、禁用「导入」按钮，避免用默认值覆盖现有偏好。
- 迁移失败的可见结果：启动时汇总为「存储恢复」banner；备份导入在页面上显示 warning 或失败原因。

## 4. 应用图标与启动屏（真实资源）

- Android：
  - `mipmap-anydpi-v26/ic_launcher.xml` 与 `ic_launcher_round.xml` 使用 adaptive icon，
    前景/背景均为 VectorDrawable，并额外提供 monochrome 单色层；
  - `values/themes.xml` 提供 `Theme.Valhalla`，`values-v31/themes.xml` 使用 Android 12+
    SplashScreen API（背景色、动画图标、图标底色、时长）；
  - `AndroidManifest.xml` 的 application/activity 均引用对应图标与启动主题。
- iOS：
  - `Assets.xcassets/AppIcon.appiconset` 提供 iPhone/iPad 与 App Store 所需全部尺寸，
    1024 图标为不透明深色底 + 信号环 + 波形；

  - `LaunchScreen.storyboard` 使用深色底、波形标记、`Valhalla` 标题与副标题；
  - `Info.plist` 使用 `UILaunchStoryboardName = LaunchScreen`；
  - `project.pbxproj` 将 `Assets.xcassets` 与 `LaunchScreen.storyboard` 加入 Resources build phase。
- 设计语言：深色底（`#0B1118`）+ 信号绿（`#3DDC97`）+ 波形/信号环，与 Android 资源一致。

## 5. 进程死亡与异常退出恢复

- 新增 `StartupRecovery`：启动时读取持久化偏好、设备档案与 OTA 断点，返回
  `None` / `Resumable` / `Invalid` 三种断点状态；运行态（扫描中、传输中）不随进程恢复，
  不会在重开后显示残留假状态。
- OTA 中断后重启：
  - 断点有效且与固件匹配 → 显示可续传与已传字节数；
  - 断点损坏或版本高于当前支持版本 → 标记为无效并说明原因，重新升级从头开始，不静默清除。
- 迁移成功的档案/断点会写回当前格式，避免每次启动重复迁移。
- 测试覆盖：有断点重启、无断点重启、断点数据损坏重启、断点未来版本重启。
