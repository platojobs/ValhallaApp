## 2. 改了什么

| 条目 | 原状 | 处理 |
|---|---|---|
| `FrameCodec.decode` | 7 处 `throw` | 拆为 `validateFrame()` 纯校验 + 单点抛错，解码变成直线 |
| `StartOtaRequest.decode` | 3 条续传扩展头规则 | 合并为 `validateResumeExtension()` 规则表 |
| `OtaController.sendChunk` | 2 条应答规则 + 冗余取消分支 | 合并为 `validateChunkAck()`；`CancellationException` 本就不在可重试集合，删掉原样重抛的分支 |
| `OtaController.resolveStartOffset` | 3 条偏移规则 | 合并为 `validateStartOffset()` |
| `SettingsScreen` | 15 参数 | 11 个回调收入 `SettingsScreenActions`（→5） |
| `ScanScreen` | 13 参数 | 7 个回调收入 `ScanScreenActions`（→7） |
| `ValhallaContent` | 10 参数 | 复用既有 `ValhallaUiCallbacks`，去掉内部重复装配（→6） |

异常类型、触发顺序与消息文本均未变化；参数对象只是把回调按语义成组，调用点行为不变。

## 3. 为什么其余 50 条不动

- **TooGenericExceptionCaught（29）**：全部是控制器/平台回调边界，且已单独重抛 `CancellationException`。
  收窄成具体异常会漏掉未知失败；收窄成 `Exception` 仍被规则命中（detekt 默认把
  `Exception`/`RuntimeException`/`Throwable` 都视为过泛）。唯一能让规则闭嘴的写法是把异常变量
  改名为 `_`，属于纯凑指标。
- **ThrowsCount（7）**：DER/PEM/固件/通知解析的每个抛点对应一种可诊断的格式错误，阈值是 2，
  压到 2 只能把 `throw` 挪进私有函数或改成「可空值 + 消息变量」，可读性会下降。
- **LargeClass（4）**：两个测试套件是各自组件唯一的端到端集合；`AppStrings` 是单一映射表，
  拆分会破坏中英同步校验；`OtaController` 剩余体积围绕同一份可变传输状态，再拆属于状态归属重设计。
- **LongParameterList（1，`DetailScreen`）**：20 个参数中状态与回调各半，收敛需改函数体内约 35 处引用。
- **ReturnCount（3）**：都是卫语句链，正是规则推荐写法。
- **SwallowedException（2）**：一条是用户取消的控制流异常，一条已转换为用户可见的 `READ_FAILED`。
- **Loop（3）/ ExplicitGC（1）**：解析与批量调度的 `break`/`continue`、基准测量的显式 GC。

逐条理由见 [static-analysis-baseline.md](../static-analysis-baseline.md)。
