# v3.2.0 - 复杂函数收口

- 版本：`3.2.0`（`versionCode 32`）
- 基线：v3.1.0（远端 `4ab01ca`）
- 主题：只处理 detekt 基线中的 `CyclomaticComplexMethod` 与 `LongMethod`，不新增功能、不新增页面

## 1. 目标与结果

v3.1.0 基线中两类规则共 34 条（`CyclomaticComplexMethod` 18 + `LongMethod` 16），
按函数去重后为 **25 个唯一函数**。v3.2.0 全部处理完毕：

| 规则 | v3.1.0 | v3.2.0 |
|---|---:|---:|
| CyclomaticComplexMethod | 18 | **0** |
| LongMethod | 16 | **0** |
| detekt 基线总数 | 95 | **57** |

- 未使用 `@Suppress`、未新增规则例外、未加 `// detekt:ignore`；
- 未把逻辑挪进 Composable 规避统计；未拆成更碎的「函数列表」凑行数；
- 基线按现状重生成，删除已消除的 38 条，剩余 57 条为 v3.1.0 就存在的历史类型。

25 个函数的前后对照（原名、原行数、原圈复杂度、拆成几个子函数、现行数与现复杂度）见
[complexity-refactor.md](../complexity-refactor.md)。摘要：

| 函数 | 原行数 / 原复杂度 | 现行数 / 现复杂度 |
|---|---:|---:|

其余 15 个函数同样降到阈值内，完整数据见对照文档。

## 2. 拆分方式

- 长 `if/else` 链与枚举分派改为 `when` + 提前返回；
- 抽取以「做什么」命名的子步骤（`validateMagic`、`tallyOutcomes`、`handleCancellation` 等）；
- 深层嵌套用卫语句拍平；
- 纯计算下沉为可单测函数（`pairRequests`、`parseDateParts`、`parseMillisOfDay`）；
- 重复分支合并（`MessageCodec` 响应解码按消息类型分发）。

## 3. 行为等价与测试

- 拆分前先确认测试覆盖；纯逻辑先补测试再动手；
- 全量测试 **772**（core 385 / data 24 / feature 363），v3.1.0 为 722，新增 **50** 个测试；
- 既有断言未修改、未删除、未放宽；
- 新增测试主要覆盖：会话编排（连接结果、断开路由、重连守卫、批量早退）、
  UI 纯逻辑（诊断报告组装、报文导出、OTA 事件）、包解析与会话状态机。

覆盖率（JVM 单元测试，`koverVerifyJvm`）：

| 模块 | v3.1.0 | v3.2.0 | 变化 | 门禁 |
|---|---:|---:|---:|---:|
| core | 94.31% | 94.17% | -0.14pp | ≥90% |
| data | 87.55% | 87.72% | +0.17pp | ≥80% |
| feature | 84.81% | 86.66% (7390/8528) | +1.85pp | ≥80% |

core 的 -0.14pp 是拆分后新增的子步骤调用行所致，波动在 0.5pp 以内；
feature 的提升来自新增的会话编排与 UI 纯逻辑测试。
