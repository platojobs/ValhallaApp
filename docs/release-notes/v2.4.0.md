# ValhallaApp v2.4.0 发布说明

- 版本：`2.4.0`（`versionCode 24`）
- 发布日期：2026-11-05
- 定位：让 App 从「能操作设备」升级到「能看懂并掌控设备」——参数面板、连接质量看板、
  首次引导、设置扩展与关于页收口

历史版本演进见 [CHANGELOG.md](../../CHANGELOG.md)，架构与协议细节见 [文档索引](../README.md)。

## 1. 版本要点

| 方向 | 内容 |
| --- | --- |
| 设备参数 | `GET_PARAM(0x0A)` / `SET_PARAM(0x09)` 接入详情页；本地校验类型/范围/字节长度；读写单在途；错误码可见 |
| 连接质量 | 独立诊断页，仅基于本机报文日志：成功率、平均/最大时延、重传、乱序、无应答、错误码分布、分命令明细、最近失败 |

| 设置 | 重连次数 1..5、退避上限 5..60 秒、日志容量 100..1000、导出默认条数/大小/单条 HEX 上限 |
| 关于 | 构建期生成版本/渠道/提交号与依赖许可清单，逐条展示依赖与许可证 |

## 2. 能力边界与关键决策

### 参数面板

- 参数表位于 `core/config/ParamCatalog`，是**协议约定值**，`confirmedByFirmware` 为 false；
  界面标题区固定显示「需固件确认」，不冒充设备上报能力。
- 编码约定：整数大端 u32、布尔 1/0、枚举单字节、字符串 UTF-8；只有表内 paramId 会展示和下发。
- 本地校验失败不会产生请求；读写共用一个在途约束（读取串行、写入期间拒绝其它读写）。
- 设备拒绝时状态回到可重试，并展示 `DeviceStatus` 错误码与文案。

### 连接质量

- 请求只统计 TX 非通知帧；同一 sequence 重复发送计为重传，时延以最后一次发送为基准；
- 应答按 sequence 配对，命令不一致的应答计为未配对；
- 乱序按应答时间顺序与请求发起顺序比较；
- 请求数少于 20 条时只显示「样本不足（X 条）」，不给出成功率/时延结论，避免把个位数
  请求包装成统计结论。

### 首次引导

- 三步可任一步跳过，完成状态写入 `onboarding_completed`；
- 引导只说明，不自动触发系统权限弹窗；「检查并授予权限」按钮调用既有权限状态机；
- 设置页可进入回顾模式，不会重置完成状态。

### 设置

- 非法输入在写入时拒绝；持久化值损坏或越界时读回默认；
- 默认：5 次重连 / 30 秒退避上限 / 500 条日志 / 200 条导出 / 512 KiB / 单条 HEX 4096 字符；
- 日志容量对新建连接立即生效，已有连接保持当前容量，超出后丢弃最旧条目。

### 关于页

- `:core:generateAppInfo` 从 `gradle.properties`、环境变量与依赖版本表生成
  `AppBuildInfo` 与 `AppDependencyInfo`；
- 提交号优先取 `VALHALLA_BUILD_COMMIT`，其次 `GITHUB_SHA`，最后 git；取不到显示「未知」；
- 许可证清单逐条展示名称、版本、许可证与作用域，不再用一句写死的文案代替。

## 3. 未验证项

- 参数表与固件的真实读写未联调，参数能力仍需固件确认；
- 连接质量统计在真机长会话下的分布与滚动性能未验证；
- 首次引导在真机上的渲染、权限按钮与系统权限框交互未验证；
- 设置页切换语言/主题后的整页刷新效果未验证；
- 关于页依赖许可清单的完整性与小屏排版需人工确认。

- JVM 测试：`core` / `data` / `feature` 全量通过；

- `verifyVersionConsistency`：`2.4.0 (code 24)`；
- CI：JVM、Android 构建、iOS Framework、Android instrumented、iOS 模拟器运行时 job；
  真实结论以仓库 Actions 页面记录为准。
